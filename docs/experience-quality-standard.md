# Learning experience quality standard

“Brilliant meets Duolingo” is the ambition for learning quality and product coherence, not a claim of equivalence and not a visual theme. The template borrows two useful product principles: focused problem solving and a clear, motivating learning path. It must earn that ambition through course-specific design, reliable state, accessible craft, and learner evidence.

## The quality bar

| Dimension | Required evidence |
| --- | --- |
| Course coherence | One visible path, clear prerequisites, meaningful module boundaries, and an obvious next useful action |
| Content coverage | Every in-scope coverage item is reviewed, deferred, or excluded with instructor approval |
| Learning rhythm | A concrete problem or prediction, concise explanation, meaningful action, explanatory feedback, and transfer where appropriate |
| Intellectual interaction | The learner predicts, manipulates, compares, constructs, traces, retrieves, explains, debugs, or decides; clicking alone is not the objective |
| Feedback and recovery | Correct and incorrect paths explain the governing rule; retry, reset, review, back, next, reload, and return remain understandable |
| Continuity | Stable state, progress, focus, and navigation preserve orientation without trapping or surprising the learner |
| Visual craft | The material-derived course direction is coherent, the important relationship is perceptually clear, controls feel responsive, and motion explains change rather than decorating it |
| Accessibility | Keyboard, pointer, narrow-screen, reduced-motion, non-colour, semantic, and text-alternative paths cover the core task |
| Evidence | Source review, automated checks, manual visual and accessibility review, instructor approval, and representative learner observation are distinguished honestly |

## Course-level experience

The home page should answer: where am I, what have I completed, and what is useful next? Keep lessons and practice in the same registry-driven journey unless a validated course need requires another model. Progress should orient rather than pressure. Do not add streaks, points, badges, timers, or locked progression without a named learning reason and an instructor decision.

Module boundaries follow coherent performances, not slide counts. The path should activate prerequisites, revisit important knowledge, and lead toward the course promise. A polished set of disconnected pages does not meet the bar.

## Module-level experience

Give each screen or section one main cognitive job. Ask for commitment before revealing the rule when retrieval or prediction matters. Make changes visible immediately, keep explanations available, and let learners inspect prior work. End with a fresh case when the objective requires transfer.

Choose the smallest representation that makes the mechanism easier to reason about. A static table or worked example can be better than a bespoke widget. Interaction earns its cost only when it exposes learner thinking or makes a relationship manipulable.

## Visual and interaction craft

- Derive the shared course theme from representative material and approved institutional guidance using `docs/theme-standard.md`.
- Preserve recognisable visual cues without copying dense layouts, inaccessible colour pairs, or unapproved assets.
- Use the shared visual system so controls behave consistently across modules.
- Keep the central task more prominent than statistics, decoration, or navigation chrome.
- Make labels, units, constraints, selected state, and consequences legible without hover.
- Preserve state across resize, theme change, navigation, and reload.
- Use motion to show causality, transition, or orientation, and respect reduced motion.
- Test actual correct, incorrect, extreme, loading, completed, malformed, and recovered states, not only the initial screen.

## Failure patterns

The following do not meet the bar:

- a page-per-slide conversion;
- generic prose wrapped in polished cards;
- click-to-reveal presented as active learning;
- every topic expressed as MCQ;
- decorative animation or gamification without a learning mechanism;
- a dashboard that obscures the course path;
- feedback that only says correct or incorrect;
- progress that loses the explanation behind completion;
- responsive layouts that technically fit but destroy the task hierarchy;
- claims of adaptivity, mastery, spaced repetition, grading, or synchronization without those systems.

## Readiness claims

Automation can establish engineering reliability. Instructor review can establish disciplinary approval. Only observation with representative learners can show whether navigation is understandable and whether the activity elicits the intended reasoning. Call an experience excellent only when these forms of evidence agree. Until then, use `pilot-ready`, `needs revision`, or `blocked`.
